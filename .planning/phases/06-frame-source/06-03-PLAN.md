<decisions>
- D6-14 Wire trace by proxy, not by trusting the code: in trace mode the driver binds `127.0.0.1:0`, `accept_async`s the Source's connection, `connect_async`s the real page WebSocket, and forwards text frames both ways, parsing each client->Chrome frame's `method` into `wire_methods: {method: count}` plus the ordered first 10 methods. The Source is started with `Source::start_ws(proxy_url, target, ...)`. This observes the bytes that actually left the recorder. The proxy is test code in tests/ and never ships.
- D6-15 SlowSink (slow mode, test code): `FrameSink` impl with its own `tokio::sync::mpsc::channel(16)` filled by `try_send` (refusals counted, max observed `16 - capacity()` recorded) and a consumer task that sleeps 300 ms per frame before calling `Encoder::send_frame`. fps 10 in, ~3.3 fps out, so the queue fills within seconds and drops must appear.
- D6-16 audit is 100/100 on this macOS build (Phase 2 baseline_audit.txt, Phase 4.1 parity); the ROADMAP/AGENTS "111/111" is a Linux figure. The pass bar here is "equal to the no-recorder baseline run on the same machine in the same session", and that baseline must itself be 100/100.
- D6-17 qol_probe runs without the recorder (it drives its own daemon/home); it is the regression check for the one upstream hook (every CdpClient in the product goes through the changed `route_cdp_text`). The battery A/B is the stealth check with the recorder attached and frames flowing (diff_oracle substitute, as in Phase 2).
</decisions>
