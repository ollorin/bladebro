<decisions>
- D6-10 No-frames rule (CAPT-05). `pub const NO_FRAMES_AFTER: Duration = Duration::from_secs(5)` + `SourceConfig::no_frames_after` (tests shorten it; Phase 7 may surface it per call; no env/config key now). Why 5 s: a visible page sends its first frame within 5 to 38 ms of startScreencast (Phase 2), so 5 s without a first frame is far outside normal; zero frames ever means hidden/minimized/occluded/stalled. Rules:
  1. Zero frames received at stop -> `SourceOutcome::NoFrames { waited_ms, hidden }`, `ok() == false`, at ANY duration (a short zero-frame capture is still blank).
  2. While running, `Source::health()` returns `Waiting` before the period, `NoFrames` after it (one `tracing::warn!(target: "bladebro.record", ...)` on the transition; stderr only, stdout untouched), `Receiving { last_age_ms }`, or `Quiet { last_age_ms, hidden }` when the last frame is older than the period.
  3. After >= 1 frame, silence is NOT a failure: an idle static page yields about one frame and that is indistinguishable from a stall without touching the page (no injected JS, no overlay, no extra method: SAFE-01). The report always carries `last_frame_age_ms`, `longest_gap_ms` and, when the tail is quiet, a note. Phase 2's 37 s mid-run stall therefore shows up as `longest_gap_ms`, not as a failure; documented as a limit.
  4. `Page.screencastVisibilityChanged { visible }` is an event Chrome sends on the screencast session (nothing is requested to get it); `visible == false` sets `hidden` and is named in the verdict.
- D6-11 Verdicts: NoFrames: `capture failed: no frames for {waited:.1} s since recording start, so the video would be blank (not a success). The tab may be in the background, minimized or covered{", and Chrome reported it hidden" if hidden}, or the screencast stalled; bring the tab to the front and record again.` Captured gains `; last frame {age:.1} s before stop` always and, when quiet, ` (no new frames for {age:.1} s: normal for a static page; a background, minimized or stalled tab looks the same, so the video holds the last frame)`.
- D6-12 Live driver = `#[ignore]` integration test `tests/record_live.rs`, run as its compiled test binary. Why this and not an example/CLI/tool: it is invisible to `cargo test --release` (ignored), never ships in the binary, adds no CLI command and no sixth tool, needs no Cargo.toml edit, and drives only the public lib API against the SAME Chrome a real `bladebro nav` daemon launched (found with env.sh `bb_port`), so the recorder sits next to the product exactly as Phase 7 will place it. A unix SIGINT (`tokio::signal::ctrl_c`) stops it gracefully (used by 06-03's long runs).
- D6-13 Wall clock for OUT-03 = Source start (after start() returns) to the stop() call, measured in the driver; drift = (ffprobe format duration - wall) / wall. Bar: |drift| <= 5 % on idle.html and tick.html (required), anim.html reported. The page-visible resize calls are HARNESS-ONLY, on a separate client, and never appear in `src/` (SAFE-01 is about the recorder's own messages).
</decisions>
