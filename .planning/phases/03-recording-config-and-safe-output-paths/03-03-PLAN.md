Write the note (< 80 lines, plain ASCII). Sections:
1. `# Windows ACL decision - recordings dir` with date and status `Decided (Phase 3)`.
2. `## Context`: on Unix the dir is 0700 and files 0600 (src/record/dir.rs). Windows has no mode bits; `src/` has no ACL handling anywhere (CONCERNS.md L37). New files and dirs inherit the parent directory's DACL. Default location is `%USERPROFILE%\.blade\recordings`; a user profile's default DACL grants the owner, SYSTEM and Administrators only, so the default dir is user-private by inheritance. A `BLADE_RECORD` dir elsewhere (e.g. `C:\shared\rec`) inherits whatever that location grants.
3. `## Options` - a table: option | how | cost | verdict:
   - A. Inherit the parent ACL (do nothing). Cost: none; safe for the default dir; a shared BLADE_RECORD location stays shared. Verdict: CHOSEN.
   - B. `icacls <dir> /inheritance:r /grant:r *<SID>:(OI)(CI)F` via `std::process::Command`. Cost: a process spawn per dir prep; needs the current user SID (by-name grants break on localized/renamed accounts); removing inheritance also drops SYSTEM/Administrators (backup, AV) and can surprise users; failure semantics unclear (warn or refuse?); not testable on this macOS host. Verdict: rejected for now.
   - C. Raw Win32 FFI (`SetNamedSecurityInfoW` with a protected DACL), in the style of `src/platform/windows_job.rs`. Cost: hand-written unsafe structs/ACE building with no CI run available to us before merge. Verdict: rejected for now.
   - D. `windows-acl` / `windows-sys` crate. Verdict: rejected - no new dependencies (DECISIONS.md D-07, Cargo.toml unchanged).
4. `## Decision`: A. Implemented now: nothing (the cfg(not(unix)) branch of src/record/dir.rs already keeps the portable checks: symlink refusal, is_dir, create_new, parent == canonical dir). The README tells Windows users that recordings inherit the directory's permissions and to keep BLADE_RECORD inside their user profile.
5. `## Revisit when`: a Windows CI runner is available to verify (then C is preferred over B: no process spawn, no SID-by-name issues), or a user reports a shared-location leak.
6. `## Verification status`: not executed on Windows (no CI run; nothing is pushed). The decision relies on the documented default profile DACL, not on a measurement.

   ```
   |---|---|---|
   | `BLADE_RECORD` | unset (off) | Absolute path: record into that dir. `1`/`on`/`true`/`yes`: on, default dir. `0`/`off`/`false`/`no`: off. Relative paths are rejected |
   | `BLADE_RECORD_FORMAT` | `webm` (VP9) | `webm` or `mp4` (H.264) |
   | `BLADE_RECORD_FPS` | `10` | Frame rate cap, 5-15 |
   | `BLADE_RECORD_SIZE` | `1280x720` | Output size `WxH`, even numbers, 160x120 to 3840x2160 |

   Unknown fields and invalid values are errors that name the file. Precedence: per-call value > env > `record.json` > default.
   Invalid values are rejected, never clamped.

   Where files go:
   - Default dir: `<data root>/recordings/`. Never under `artifacts/` (artifacts rotate at 300 files); nothing in bladebro rotates or deletes recordings.

   - Unix: the dir is set to `0700` (an existing `BLADE_RECORD` dir is tightened too - use a dedicated directory), files are `0600`. A symlinked dir is refused.
   - Windows: files inherit the directory's permissions. The default under `%USERPROFILE%` is private to your account; keep `BLADE_RECORD` inside your profile.
   ```
