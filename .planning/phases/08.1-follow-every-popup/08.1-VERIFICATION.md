## Honesty of the stated caveats

- **Window-feature popup does not return to the opener on opener input:** true. Reproduced in `popup-measure`: after `press Tab` the rows were ` R popup` / `*  opener` with the differ footer, and stop names the agent tab. The docs state it plainly. Consequence (documented, not hidden): while such a popup is open, the agent's work on the opener is not in the video.
- **"No live blocked case":** too strong. A popup inside a sandboxed iframe without `allow-popups` is blocked even with `--disable-popup-blocking`. I reproduced it live, and the behaviour is correct (one segment, no note). The docs sentence "a popup that Chrome blocks is never a tab, so it produces no segment" is accurate. Only the SUMMARY's wording overstates the absence.
- **Open-tab delay unmeasured live:** the docs honestly say "by code reading". Not re-measured here either.
- **SC3 reachability:** met through the criterion's own alternative clause. The two markers and the differ footer make the disagreement visible in `state tabs`, and the stop note names agent vs video at stop. Mid-recording disagreements that end before stop show only in the segment list, not in a note. This matches what the criterion requires.

## Non-blocking notes

1. Documented follow-delay figures are from a single session and are not a stated bound. This run measured js up to 0.21 s (daemon) and 0.28 s (MCP), against the documented "0.06 s" and "0.00-0.17 s". By code reading the bound after the popup reaches the front is about 0.3 s settle + 0.2 s poll + connect. Consider documenting that bound.
2. Docs say a `rel=noopener` popup "is never counted into the popup family". Once followed, it becomes a root (`note_followed`), so its own popups are followed as family. The behaviour is the better one; the sentence is slightly inexact.
3. Not covered: Linux/Windows, headed mode, the `real` lane, diff_oracle (python websockets missing, as in prior phases), the per-tab cap live. These match the prior phases' coverage limits.
