## Findings
- A window.open WITH window features opens its own window. Input on the opener (`act press Tab`) does NOT re-front the opener, so the video stays on the popup until it closes or the agent switch-tabs. Other popup kinds return to the opener on the agent's next input.
- Bladebro's Chrome runs with `--disable-popup-blocking`, so a gesture-less window.open is a real tab and is followed. There is no live "blocked" case; the scenario named `blocked` checks that the followed-popup behaviour holds.
- A burst of three clicks: a popup that was never in front is named in the stop note ("not recorded (never in front)"); which popup gets the note depends on timing.
- Closing the last tab makes Chrome exit. Stop reports "no tab left", keeps the file, and the file decodes.
- Harness-only fixes (not product bugs): the blue threshold in the tone check (fixture blue is g=64), a sampling race in one MCP test, and a cleanup sweep that matched its own tooling shell.
