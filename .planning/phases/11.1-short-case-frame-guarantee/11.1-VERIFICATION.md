### Adversarial checks

- **Hub lock:** the agent's stop holds the global hub mutex up to 2 s longer. The guard tick waits on the lock and then sees `Gone`. `state tabs` (`own_target`) and `finish_best_effort` cannot overlap a stop: the MCP serve loop and the daemon loop handle a call inline, and they only select on signals while reading the next request, so a signal is handled after the stop returns. The wait holds no async lock across an await (`first_ts` takes the sink's sync mutex briefly). I found no deadlock path.
- **Frame at the deadline:** if a frame is accepted after the loop exits but before `mark_end`/`retire`, it is in the encoder, and the report's frame count comes from encoder stats, so the result is "saved". If it lands after `retire`, the generation filter drops it and the result is "no frames" with a 0-byte file. Either outcome is consistent.
- **Closed tab:** `src.is_finished()` ends the wait. A mutation removing that check makes `no_wait_when_the_tab_connection_ended` fail.
- **Per-tab:** only the followed (current) tab's capture is awaited. The per-tab live runs and `per_tab_late_first_frame_is_awaited` (production default wait) pass.
- **Regression tests vs old code:** in a scratch worktree I restored the old `agent_vs_video` comparison and a zero wait. Four tests then fail: agent_vs_video, late_first_frame, per_tab_late, and no_frame_in_the_wait (the last one because the old code does not wait at all).
