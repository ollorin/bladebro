<objective>
Make a QA case that stops within ~0.5 s of `record-start` on a static page end with a playable video of at least one frame, and stop the stop note from contradicting itself.

Root cause (from code reading + 11-03 evidence; confirmed live in Task 5): the source subscribes to events BEFORE `Page.startScreencast` (src/record/source/capture.rs `start_ws`, comment "Subscribe before starting so the first frame cannot be missed"), and the encoder is running before the source starts (machine.rs `start`), so no frame is lost or dropped on our side. The first frame simply has not been produced yet: `record-stop` immediately ends the video and the source sends `Page.stopScreencast`, which Chrome processes before it emits that first frame. In 11-03 the same static page delivered frames steadily once started (1 s wait: `captured 12`, 11 frames, 1.1 s), so the first frame comes a few hundred ms after start. Therefore: no CDP nudge (no repaint, no screencast restart; the CDP method trace stays exactly the same) - the agent's stop waits, bounded, for the first frame.

Design:
- The wait lives in the follower's stop path (`Run::finish`, moved to the new `src/record/hub/follow/stop.rs`, a `#[path]` child of `run.rs` like `hub/finish.rs` is of `machine.rs`), BEFORE `self.policy.mark_end()` and `self.retire(false)` (which sends `Page.stopScreencast`).
- The first frame is observed exactly like the existing catch-up wait does: `Policy::first_ts(tab, gen)` (set by `SegmentSink` only after the encoder ACCEPTED the frame; per-tab: that tab's file), polled every 10 ms.
- The wait ends at the first of: first frame accepted; deadline `FIRST_FRAME_WAIT` (2 s, `pub const` in follow.rs); `seg.start + no_frames_after - 100 ms` (never stretches a silent segment into the 5 s no-frames failure); source loop finished (tab closed / connection lost); source health already `NoFrames` (its no-frames verdict); follower `lost`; no current capture (per-tab parked).
- The duration travels with the stop request: `Tracker::stop(hint, first_frame_wait)` sends `StopReq { hint, first_frame_wait }`. `finish_active` passes `FIRST_FRAME_WAIT` (or `Knobs.first_frame_wait` in tests) only when `extras.is_some()` (agent `record-stop`); `finish_orphan` / `interrupt_if` / `stop_on_limit` pass `Duration::ZERO`, so the exit bound in exit.rs and the docs is unchanged.
- `msg::agent_vs_video` strips `NO_FRAMES_LABEL` (" (no frames)") from the video label before comparing.

Output: fork-owned code + tests, a repeatable live check, docs, deferred-items update, evidence.
</objective>
