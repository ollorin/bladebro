# 11.1-01 Summary: record-stop first-frame guarantee and bare ids in agent_vs_video

## Outcome

A short QA case that starts and stops within about 0.5 s on a static page now saves a playable file with at least one frame, in MCP, daemon and per-tab modes. The assertion-only case, which previously failed with `no frames reached the encoder`, now saves. `agent_vs_video` compares bare tab ids. Code changes are confined to `src/record/**`, and the docs, the tools and the deferred-items update are limited to the 11.1 scope. `.planning/HOOKS.md` is unchanged and there is no upstream change.

## Design (5 lines)

1. The agent `record-stop` path waits in the follower's stop (`src/record/hub/follow/stop.rs`) for the current capture's first frame, before the screencast is stopped.
2. The wait observes `Policy::first_ts`, which is set only after the encoder accepted a frame, and it polls every 10 ms.
3. The wait ends at the first of: a frame accepted, the `FIRST_FRAME_WAIT` deadline (2 s), `seg.start + no_frames_after - 100 ms`, the source ending or reporting NoFrames, the follower being lost, or no current capture.
4. The wait duration travels with the stop request (`StopReq { hint, first_frame_wait }`). Exit paths (`finish_orphan`, `interrupt_if`, `stop_on_limit`) pass `Duration::ZERO`, so exit-path timing is unchanged.
5. `msg::agent_vs_video` strips the ` (no frames)` label before comparing ids.
