  <name>Task 1: Tab-following, attach-wait and scripted actions in the sidecar</name>
  <files>tools/record_sidecar/lib/follow.mjs, tools/record_sidecar/sidecar.mjs</files>
  <action>
**lib/follow.mjs** (pure, exported):
- `pickActiveFromList(list)` -> id of the first entry with `type==="page"` and a url not starting with `devtools://` (Chrome's /json/list is expected to be ordered most-recently-active first; Task 2 verifies this live), or null.
- `shouldSwitchOnCreated(targetInfo, mode)` -> true when mode is `newest` and `targetInfo.type==="page"` and not `devtools://`.
- `parseScript(str)` -> sorted `[{atS:number, action, arg}]` from `"5:emulate=1001x641;15:window=1100x700;25:emulate-clear;30:minimize;40:restore"`; actions allowed: `emulate=WxH`, `emulate-clear`, `window=WxH`, `minimize`, `restore`; throws on anything else.
- `findNewestActivePort(entries)` -> given `[{path, mtimeMs, text}]` pick newest mtime and return `parseDevToolsActivePort(text).port` (import from cdp.mjs); null if empty.

**sidecar.mjs** additions:
- `--follow off|newest|poll` (default off), `--poll-ms N` (250). After attach, always send `Target.setDiscoverTargets {discover:true}` on the browser session (no sessionId) when follow != off.
  - `newest`: on `Target.targetCreated` where `shouldSwitchOnCreated` -> `switchTo(targetInfo.targetId)`.
  - `poll`: every pollMs `getJson(port,'/json/list')`, `pickActiveFromList`; if it differs from current -> `switchTo(id)`. Also apply on `Target.targetDestroyed` of the current target.
  - `switchTo(id)` (serialized with a promise chain, never concurrent): `Page.stopScreencast` on old S (ignore errors), `Target.detachFromTarget {sessionId:S}`, `Target.attachToTarget {targetId:id, flatten:true}` -> new S, `Page.enable` (unless --no-page-enable), `Page.startScreencast` (same params). The frame handler compares the event's sessionId to the CURRENT S; frames from a stale session are still acked (with their own sessionId) but counted in `stale_frames` and not enqueued. The encoder process is NOT restarted. Push a segment `{t_ms, targetId, url, frames:0}`; per-segment frame counts increment in the handler. Record `switch_ms` (time from decision to first frame of the new segment) in the segment.
- `--attach-wait S --blade-home DIR`: instead of `--port`, poll every 50 ms (up to S seconds) for `DevToolsActivePort` files under DIR (recursive, depth <= 4) whose mtime is newer than sidecar start minus 2 s; use `findNewestActivePort`; then poll `/json/list` until a page target exists; attach to it. Exit 3 with `no browser appeared` if the deadline passes. Used by 02-03 to attach to `bladebro audit`'s own browser.
- `--script "<spec>"`: at each `atS` run the action through the browser connection: `emulate=WxH` -> `Emulation.setDeviceMetricsOverride {width,height,deviceScaleFactor:0,mobile:false}` on S; `emulate-clear` -> `Emulation.clearDeviceMetricsOverride` on S; `window=WxH` -> `Browser.getWindowForTarget {targetId}` then `Browser.setWindowBounds {windowId, bounds:{windowState:'normal'}}` then `{bounds:{width,height}}`; `minimize` -> `{bounds:{windowState:'minimized'}}`; `restore` -> `{bounds:{windowState:'normal'}}`. Log `{t_ms, action, ok, error}` to stats `events`. Put the script-action runner in `lib/actions.mjs` (not inline) so sidecar.mjs stays under ~500 LOC and each file holds one responsibility (CDP capture loop vs harness actions vs follow policy). Comment in code: harness-only, Emulation is page-visible and must never appear in the product recorder.
- Browser gone (WS close or `Target.targetDestroyed` with follow off): run the normal stop sequence (finalize whatever was captured), stats `stop_reason:"browser-gone"`. Other stop reasons: `duration`, `signal`.
- Add stats keys: `stale_frames, stop_reason, follow, segments[].switch_ms`.
  </action>

<task type="auto">
  <name>Task 3: Core measurements - fps, ack latency, slow consumer, 60 s frames vs acks, idle drift</name>
  <files>tools/record_sidecar/scenarios/core.sh, tools/record_sidecar/results/core.json</files>
  <action>
`scenarios/core.sh` runs these groups. Each group is its own headed browser session (`$BB nav ...` at start, `$BB stop` at end, <= 2 min). Every run: `node $RS/sidecar.mjs --port $P ... --out $SCRATCH/<name>.webm --stats $SCRATCH/<name>.stats.json` then `node $RS/measure.mjs merge <name> ...` appended to a JSON array; at the end write `results/core.json` as `{host:{os:"macOS arm64", chrome:<from stats.chrome>, ffmpeg:"n9.0.2"}, runs:[...]}`.

Group A (anim.html, ~75 s):
- `fps_default`: 20 s, vp9, wallclock, defaults (1280x720 cap, q70, everyNth 1).
- `fps_nth2`: 15 s, `--every-nth 2`.
- `slow_consumer`: 20 s, `--slow-writer-ms 200 --queue 8` -> expect frames_dropped > 0 while acks_sent == frames_received.

Group B (anim.html, ~70 s):
- `acks_60s`: 60 s, vp9 wallclock. Report frames_received, acks_sent, acks_ok, acks_err, fps_buckets (look for stalls: any 1 s bucket == 0 after the first frame), max_gap_ms.

Group C (idle.html, ~105 s): three 30 s runs on the SAME idle page: `drift_wallclock` (`--ts wallclock`), `drift_concat` (`--ts concat`), `drift_cfr` (`--ts cfr --fps 10`). Then a fourth 10 s run `drift_wallclock_notail` (`--ts wallclock --no-tail`) to show the effect of the tail frame. If 4 runs exceed 2 min, split into two sessions.

After all groups, append a `derived` object to core.json computed by a small `node -e` over the runs (never by hand): `effective_fps` (fps_default.effective_fps_recv), `ack_send_us_p95`, `ack_rtt_ms_p95`, `slow_consumer_drop_pct` (frames_dropped / frames_received * 100), `frames_eq_acks_60s` (acks_sent === frames_received and acks_err === 0), `stall_seconds_60s` (count of zero buckets after first frame), and `drift_pct` per strategy plus `within_5pct` booleans.

If a run fails, keep its entry with `exit_code`, `encoder.stderr_tail` and `error`; do not drop it.
