<decisions>
- D7-1 Placement (CONTEXT): process-global `static HUB: OnceLock<tokio::sync::Mutex<Hub>>` lives in hub.rs (Hub is not generic; each op takes `&impl HubEnv`) and is a trivially thin wrapper; ALL logic is on `Hub` instances so tests never touch the global (research risk 9). In this plan the global holds `Hub` and exposes `finish_best_effort()`; the Page adapter (`try_handle`) arrives in 07-02 with the `Page::base` hook.
- D7-2 Injection: `pub(crate) trait HubEnv` (env.rs) with `fn config(&self, name: &str) -> Result<RecordConfig, String>` (live: `resolve_from_env(&RecordOverrides{name: Some(..), ..Default::default()})`), `async fn ffmpeg(&self) -> Result<ResolvedFfmpeg, EncoderError>` (live: `resolve_ffmpeg()`), `fn lane(&self) -> Lane`, `async fn current_tab(&self) -> Result<String, String>` (live in 07-02: `Target.getTargetInfo` on the page session), `fn attach(&self) -> Attach`. `enum Lane { Ws, Pipe, Ephemeral, Real }`; `enum Attach { Port(String), Ws(String) }` (`Ws` = FakeCdp url for tests -> `Source::start_ws`; `Port` -> `Source::start(&Endpoint::Port{base})`).
- D7-3 Start order (cheap first, research 6): validate name (non-empty string) -> lane refusals (Real, Ephemeral, Pipe) -> Active? (CTRL-05 error) -> `config()` and `enabled` gate (off -> refusal, nothing created) -> `ffmpeg()` -> `current_tab()` -> `create_recording_file` -> `EncoderConfig::new` + `Encoder::start` -> `Source::start*`. Source failure: drop the sink, `finish()` the encoder, `remove_file` the path this call created, return the SourceError text. Encoder start failure: remove the file, return EncoderError text.
- D7-4 Stop: `src.stop().await` -> `take_encoder(arc, 20, 50 ms)` (retries `Arc::try_unwrap`; on failure return Err "recording not finalized: the frame source did not release the encoder within 1 s; the file <path> may be incomplete. Browsing is unaffected.", never `expect`) -> `enc.finish().await` -> `report::compose(..)`. Hub returns to Idle in every branch. `current_tab()` at stop: if it differs from the bound id, append the note `agent is now on tab <id>; the video shows only tab <bound> (tab following is not implemented yet)`; a `current_tab` error is ignored (no note).
- D7-5 Report (OUT-05, CONTEXT "Ok only for Captured+Finalized"): fields line `<abs path> (bytes N, duration D.D s, frames N, dropped N, segments [0.0 s tab <id>])`; duration = `frames_written as f64 / fps` (encoder's constant-rate stamping; no ffprobe); dropped = `enc.frames_dropped + src.stats.lost` (queue drops are already counted once by the encoder: do not add the source's queue_dropped); append `, captured N` (= `src.stats.forwarded`) only when it differs from frames_written. Ok text: `recording saved: <fields line>` + the source verdict's quiet-tail note when present + tab note. Err text: `recording not clean: <first failing verdict (encoder verdict if encoder not Finalized, else source verdict)>; <fields line>` + notes. `segments` keeps the shape `[<at_s> s tab <id>, ...]` so Phase 8 appends.
- D7-6 Messages (msg.rs, all ending "Browsing is unaffected." where they are failures; the actionable recovery named):
  - off: `recording is off: the operator has not enabled it. Set BLADE_RECORD=1 (or record.enabled in .bladebro.json / record.json), then run bladebro stop (or restart the MCP server) so it is re-read. Nothing was recorded.`
  - ephemeral: `recording needs a long-lived session: use the MCP server or the daemon (bladebro without --no-daemon/--port); one-shot CLI exits after each command. Nothing was recorded.`
  - pipe: the existing `SourceError::PipeTransport` Display.
  - real lane: `recording is not available in the real-browser lane (it would capture your own browser). Nothing was recorded.`
  - active (CTRL-05): `recording already active: <abs path> (started N.N s ago, <health>). record-stop it first.` where health is `receiving` / `waiting for first frame` / `no frames yet (tab hidden or in background?)` / `quiet N.N s`.
  - none: `no active recording; record-start <name> first.` If an orphaned report is stored (D7-7) it is returned instead, prefixed `previous recording ended with the browser: `, with that report's Ok/Err.
  - bad name: `record-start needs name (a string), e.g. state record-start login-flow.` (BladeError::Usage at the adapter in 07-02; here a typed `HubError::Usage`).
  - `scrub(s)` replaces the four dead-tab substrings with `tab gone`; every outgoing text passes through it.
- D7-7 Orphan: `Hub::finish_orphan().await` stops an Active recording exactly like stop and stores the result text as `orphaned: Option<(bool, String)>`; used by `finish_best_effort()` (07-02 calls it on browser shutdown and surface exit). The next stop returns it; the next start prepends it as one line before `recording started: ...`.
- D7-8 Start Ok text: `recording started: <abs path> (tab <id>); first frame not awaited. record-stop saves it.` Do not wait for a first frame (research 4).
- D7-9 Threat model (recording captures whatever the page shows, incl. credentials, SAFE-03; not money/auth, listed for completeness): (a) agent starts capture on a machine whose operator never opted in -> `enabled` gate in the hub, server side, env/config only, no per-call bypass; (b) two concurrent starts race -> the tokio Mutex is held across the whole op, second sees Active; (c) a crash-retry replays record-start -> `retry_safe` allowlist (mcp/server.rs) already excludes it, do not touch; (d) caller name traversal -> `create_recording_file` sanitizes (Phase 3); (e) half-applied start (ffmpeg up, no source, stray empty file) -> D7-3 cleanup, tested. Atomicity: Hub transitions to Active only after both Encoder and Source started.
</decisions>
