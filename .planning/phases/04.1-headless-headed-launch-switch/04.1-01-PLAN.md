<decisions>
- D41-1 Spellings: one shared word parser `pub fn parse_switch(t: &str) -> Option<bool>` in src/record/values.rs (`1|on|true|yes` -> true, `0|off|false|no` -> false, case-insensitive, trimmed); `parse_record_env` is refactored to use it so BLADE_RECORD and BLADE_HEADLESS can never diverge.
- D41-2 Semantics: the only meaningful bit is "headless forced". BLADE_HEADLESS=0 and unset behave identically on every OS (macOS/Windows native window; Linux Xvfb, honest fallback). `0` exists to override a lower layer (project/user file) that says headless. On Linux "headed" means headful on bladebro's private Xvfb display (invisible to the user by design, best stealth); showing a window on the user's own Linux desktop is NOT offered (the managed lane strips Wayland and pins X11 to Xvfb). Docs say so.
- D41-3 Resolution is pinned once per process (`effective()` caches the first Ok in a `OnceLock`; errors are not cached). Daemon and MCP keep one mode for their lifetime; a GL-ladder relaunch or crash relaunch never flips mode. `resolve_now()` is the uncached form (status/toggle in 04.1-02).
- D41-4 Launch note: printed once per process (AtomicBool latch) on the first managed launch: `[bladebro] browser mode: <desc> (source: <label>)`. desc: `headless` | `headed` (macOS/Windows) | `headed (virtual display)` (Linux + Xvfb) | `headless (no Xvfb; fallback)` (Linux, not forced, Xvfb missing). label: `env BLADE_HEADLESS` | `project file <path>` | `user config <path>` | `default`.
- D41-5 Advisory honesty: `pending_notes()` HEADLESS_NOTE gets `&& !crate::launch_mode::headless_by_request()`; forced headless is reported by the stderr launch note, not by a false "Xvfb missing" note in every agent response.
- D41-6 The existing `[bladebro] launching Chrome ... (<mode_str>)` line on macOS/Windows must stop saying `headful` for a headless launch: non-Linux `mode_str` becomes `if headful { "headful" } else { "headless" }`.
- D41-7 Error string (exact prefix tested): `BLADE_HEADLESS: "<v>" is not valid; use 1/on/true/yes (hidden browser) or 0/off/false/no (visible browser), or unset it for the platform default`.
</decisions>
