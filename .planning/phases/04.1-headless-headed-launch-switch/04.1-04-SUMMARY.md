# 04.1-04 Summary: headless audit parity

Problem (macOS, Chrome 154): `BLADE_HEADLESS=1 audit` 97/100, headed 100/100.

Diagnosis (measured):
- Headless Chrome reports a 800x600 screen (and avail) when `--window-size` is not pinned; `--window-size` alone does NOT change `screen.*` in `--headless=new`. `--screen-info={1920x1080}` does (screen 1920x1080, avail same, inner 1920x993).
- After `Network.setUserAgentOverride` without `userAgentMetadata`, `navigator.userAgentData` has empty brands/platform/high-entropy values. The probe is only readable in a secure context (about:blank gives undefined), so at attach time the metadata is derived.

Fix:
- `src/launch_mode/display.rs::pin_headless_window` + 2 flags (`--window-size=1920,1080`, `--screen-info={1920x1080}`) for headless on non-Linux only (Linux unchanged: not measured to need it).
- `src/launch_mode/uad.rs`: probe the browser's own userAgentData when readable (HeadlessChrome renamed to Google Chrome), else derive from the real UA version using Chromium's deterministic GREASE/shuffle algorithm (Chrome 154 yields exactly the headed list `Chromium/154, Google Chrome/154, Not A(Brand/99`). Falls back to old behavior when the UA cannot be parsed. CDP-level only; no JS patch.
- Hooks listed in .planning/HOOKS.md.

Verification: fmt, clippy -D warnings, `cargo test --release` green (new tests: 4 in uad.rs, 1 in display.rs). Fresh scratch BLADE_HOME each: headless audit SCORE 100/100 VERDICT PASS exit 0; headed 100/100 PASS exit 0. qol_probe: 120/122 both before and after the change (the 2 failures, "chord cleared the live editor" and "nested scroller movement", pre-exist on the unmodified tree). No leftover daemon/Chrome processes.
