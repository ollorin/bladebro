### Findings (severity, repro, fix)

**G1 Medium: poisoned daemon** (confirms the first-pass finding; it breaks HEAD-03, it is not "non-blocking").
Repro (cwd = scratch dir, `BLADE_HOME=h2`): `BLADE_HEADLESS=maybe bladebro nav http://127.0.0.1:18765/` prints `daemon failed after auto-start (...)`, then one-shot fails; `pgrep -fl "bladebro daemon"` shows the daemon still up. Then `BLADE_HEADLESS=1 bladebro nav ...` and unset `bladebro nav ... --json` both return the stale `BLADE_HEADLESS: "maybe" is not valid` until `bladebro stop` (the idle timeout is 600 s). Root cause: `run_tool` auto-starts before `request_tag()` validates; the daemon inherits the env; `effective()` correctly doesn't cache errors, but the daemon's env never changes.
Fix: (a) `src/cli.rs` run_tool, first statement inside `if !no_daemon { #[cfg(unix)] {`: `crate::launch_mode::request_tag().map_err(BladeError::Other)?;` (lane-aware; one HOOKS.md row). (b) `src/launch_mode/daemon.rs` `daemon_mismatch`: `Err(e) => Some(format!("this daemon was started with an invalid launch setting ({e}); run `bladebro stop`, then retry"))`. (c) Add a wiring test asserting the validation precedes `auto_start_daemon()`.
MCP lane with an invalid value: no startup failure. The first tool call returns `✗ Could not launch Chrome: BLADE_HEADLESS: "maybe" is not valid ... Check that Chromium is installed and try again.` The suffix is misleading (src/mcp/server/serve.rs:294; Low). Suggest an `eprintln!` warning at MCP boot when `launch_mode::request_tag()` errors, and dropping the Chromium suffix for launch-config errors.

**G2 Medium: launch note invisible on the default CLI path.** Repro: `BLADE_HEADLESS=1 bladebro nav http://127.0.0.1:18765/ 2>e1.txt; grep -c "browser mode" e1.txt` gives 0 (daemon stderr is `Stdio::null()`). Fix: after `auto_start_daemon()` succeeds, the client prints `launch_note(&effective()?, ...)` to stderr. Stderr only, so no agent tokens. The headful bit is predictable for the forced and macOS/Windows cases; on Linux print the requested mode. Alternative: state in the page that the daemon path shows the mode only via `bladebro headless status`/doctor.
