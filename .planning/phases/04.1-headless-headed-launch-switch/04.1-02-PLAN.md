<decisions>
- D42-1 Files: project `.bladebro.json` = `{ "headless": bool, "record": { enabled, dir, format, fps, size, quality } }` (both levels `deny_unknown_fields`; `record` reuses `crate::record::FileConfig`). User launch file `<data root>/launch.json` = `{ "headless": bool }`. User recording file stays `<data root>/record.json`.
- D42-2 Walk-up (pure `find_project_file(start, home, exists, is_repo_root)`): from cwd upward; return the first dir's `.bladebro.json`; stop BEFORE reading when the dir equals home (so `~/.bladebro.json` is never a project file; user settings belong in launch.json); stop AFTER a dir containing `.git` (repo boundary: a parent folder's file cannot steer a checkout); stop at the root; max 64 levels. Home is canonicalized when possible before comparing.
- D42-3 Trust (Unix): the project file must be a regular file, not a symlink (checked with symlink_metadata; not followed), owned by the effective uid and not group/other-writable; otherwise it is IGNORED with a stderr warning naming the path and reason (a planted file in a shared parent must not break or steer runs). Windows: no owner/mode check (documented). Oversized (>64 KiB), invalid JSON, unknown keys or bad values are ERRORS naming the file (strict like record.json; error text lists fields `headless, record`).
- D42-4 Project `record.dir` (vet_project_dir): relative paths join the project root; result is resolved with `record::dir::resolve_lenient` (canonical existing ancestor, so symlinked subdirs are followed); accepted only if inside the canonical project root or inside the canonical `<data root>/recordings` (NOT anywhere in the data root: that would allow `<data root>/sessions` or the profile dir); otherwise dropped with warning `<path>: record.dir <d> ignored: must be inside the project (<root>) or <data root>/recordings` and the next layer/default applies. A project-local recordings dir should be gitignored (docs say so). Other project record keys (enabled, format, fps, size, quality) are allowed. The artifacts guard in `resolve` still applies afterwards.
- D42-5 Precedence for recording: format/fps/size per-call > env > project > record.json > default; enabled env > project > record.json > false; dir env > project (vetted) > record.json > `<data root>/recordings`; quality project > record.json > 70. Project errors are prefixed `<path> record.<key>:`.
- D42-6 Daemon (HEAD-03), least invasive correct option = refuse with a plain message, never auto-restart (a restart would kill another session's browser; `rb on|off` restarts because the user asked for a lane switch, this is an implicit env difference). The CLI adds `"launch": {"headless": bool, "source": label}` to every daemon request; the daemon compares with its pinned `effective()` (skipped on the real-browser lane, and when the field is absent, e.g. `stop`). Message (exact start tested): `browser mode mismatch: the running daemon's browser is <headed|headless> (source: <d>) but this command resolves to <headless|headed> (source: <r>). Run \`bladebro stop\`, then retry; the next command starts the browser in the requested mode.` It must not contain "Connection refused", "No such file" or "daemon not running" (those make run_tool restart the daemon). MCP: mode from its own env/cwd at first launch, pinned; restart the MCP server to change. Windows has no daemon (one-shot), so no mismatch can arise there.
- D42-7 Toggle output (human): `on`/`off` -> `headless: on (saved to <path>)` + newline + status line + newline + `applies at the next browser launch; run \`bladebro stop\` first if a daemon is running`. `status` -> `browser mode: <headless|headed|platform default> (source: <label>)` and, when the user file is overridden by env/project, a second line `user config <path> says <on|off> but <label> takes precedence`. `--json`: one object `{"ok":true,"is_error":false,"text":<same text>}`. Unknown subcommand -> `BladeError::Usage("usage: bladebro headless on|off|status")` (exit 2).
- D42-8 Doctor: name `Browser launch mode`; detail `headless (source: ...)` | `headed (source: ...)` (macOS/Windows) | `Xvfb headful, headless fallback (source: ...)` (Linux, not forced); resolution error -> Fail, detail = error, fix `fix or remove the named setting; see docs/recording-and-launch-config.md`.
</decisions>
