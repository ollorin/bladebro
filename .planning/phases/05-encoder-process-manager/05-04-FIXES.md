# 05-04 Gap-closure fixes (Phase 5 verification gaps)

1. **T5 honesty (writer abort).**
   - Before: if `finish()` aborted the writer after 10 s of pending writes, ffmpeg got EOF, exited 0, and the report said Finalized with "0 dropped" although queued frames were discarded.
   - After: the writer counts fully written source frames (`Shared.frames_done`); on abort `finish()` records `frames_unwritten = queued - frames_done` in the new `EncoderReport.frames_unwritten`. `classify` returns the new `Outcome::Truncated { unwritten }` for exit 0 + non-empty file + unwritten > 0 (real failures keep their more specific outcomes). Verdict: "recording truncated: ... N queued frames were not written (video is shorter than the capture)". `frames_dropped` is unchanged (queue-full drops only), so existing queued+dropped invariants hold.
   - Tests: `writer_abort_is_reported_as_truncated` (fake that starts reading 1 s late, 3 x 64 KiB frames 600 s apart, 500 ms finish timeout, fast); `classify_table` abort rows; verdict table row for Truncated.
2. **Matrix flakiness under load.** `j_idle_hold_flushes_before_finish` first waits (bounded poll, `wait_for_file`) for the fake to create its output, then holds, then bounded-polls the size; frame range loosened. Fake-test finish timeouts 5 s -> 15 s and wall-clock bounds 7 s -> 20 s. The new truncation test waits for the fake's `.up` marker before starting.
3. **Windows w4 / comments.** w4 now points at a nonexistent `.exe` (CreateProcessW rejects it; `.cmd` is run by cmd.exe and is not existence-checked). process.rs comment: abort delivers EOF on unix; on Windows a blocked write may keep the pipe open and the kill fallback bounds finish. windows_tests.rs batch-escaping note now says "uncertain, not run". Still not compiled or run on Windows.
4. **Verdict nits and docs.** Signal exits and exit code 255 (ffmpeg's SIGINT) say "may be incomplete and was not verified" instead of "is not a valid recording". Docs: worst-case finish about 18 s (10 + 2 + 5 + 1), ffmpeg 4.3 requirement is not checked in code (older ffmpeg fails at encode time with its exit error), truncated outcome described. crf unchanged (40).
