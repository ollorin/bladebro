- D9-2 Post-loop ordering: move the existing hook line (daemon.rs:452) above the login snapshot block (:445-451). Net 0 lines; the HOOKS.md row for Phase 7 gets a Phase 9 row "moved above login snapshot".
- D9-3 Process group: in fork-owned encoder/process.rs, `#[cfg(unix)] cmd.process_group(0);` on the tokio Command (tokio exposes `process_group` on unix; if not on the pinned tokio version use `std::os::unix::process::CommandExt` via `as_std_mut()`; confirm with `cargo check`, MSRV 1.86). Rationale comment: terminal SIGINT would otherwise hit ffmpeg and race finish (encoder/report.rs exit 255 classification); a parent crash still finalizes because ffmpeg exits on stdin EOF (09-RESEARCH empirical: <=250 ms, file decodes). Windows untouched (no console process group; CREATE_NO_WINDOW flags already set).
- D9-4 Signals: no new handlers. MCP: boot.rs wait_for_shutdown_signal (SIGTERM/SIGINT/SIGHUP; Windows ctrl_c) -> serve.rs break -> post-loop shutdown_browser -> finish. Daemon: daemon.rs:24-40 SIGTERM/SIGINT (SIGHUP ignored by design) -> break -> post-loop finish. A second signal during finish is swallowed by the tokio handler (process stays until finish is bounded, max ~18 s); a supervisor SIGKILL still finalizes via stdin EOF. Windows: only ctrl_c; console close/logoff/shutdown events are not handled (would need SetConsoleCtrlHandler = upstream architecture change; NOT done, documented as a gap; stdin EOF + job object cover hard kills, a TerminateProcess leaves an unfinalized file).
- D9-5 MATRIX (exit.rs, pure const, used by docs and a completeness test): rows = record-stop, recorded-tab close (follow / per-tab), MCP stdin EOF, MCP SIGTERM/SIGINT, MCP idle, daemon SIGTERM/SIGINT, `bladebro stop`, daemon idle, relaunch drift/crash/Closed (mcp + daemon), one-shot exit, kill -9 parent, kill Chrome, kill ffmpeg, disk low/max duration/max size. Columns: lane (mcp/daemon/oneshot), outcome (`finalized` | `finalized, reported at next record op` | `interrupted, partial kept` | `refused (no recording possible)` | `self-finalized by ffmpeg on stdin EOF`), test (test fn name, or `live: exit_live.sh <id>` for kill -9/signals, or `09-02`/`09-03` for rows those plans implement). Rows owned by 09-02/09-03 are present now with `planned: 09-0N` and the completeness test accepts that marker only until those plans replace it (09-03 removes the marker branch).
- D9-6 Hub-level testing of daemon hooks without a daemon: the hook is a call of `finish_best_effort`; exit_tests drive the SAME sequence on a Hub with TestEnv (start -> source dies or not -> `finish_orphan` -> next stop/start returns prefixed report, and a new start succeeds).
