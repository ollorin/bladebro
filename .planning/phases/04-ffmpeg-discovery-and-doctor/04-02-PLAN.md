<decisions>
- D4-8 Status rule (user decision): WARN only if ffmpeg is missing, BLADE_FFMPEG is unusable (not found / not executable / probe failed), the probe of a PATH/known ffmpeg failed, the encoder list is unreadable, the configured format's encoder is missing, or the configured format could not be read (bad config: format availability is then unknown, D4-10). Everything else is PASS. Never FAIL: recording is opt-in, doctor must not exit non-zero for it.
- D4-9 Old version (major < 4, D4-6) stays PASS when encoders are fine but the line says "(old; 4+ recommended)". This honors the explicit WARN list above; flag in the SUMMARY so the coordinator can flip it to WARN if preferred.
- D4-10 Bad record config: `resolve_from_env` Err -> evaluate as WebM, level WARN, detail ends with "; record config unreadable, assumed webm", fix carries the resolver error (it names its source, e.g. BLADE_RECORD_FORMAT or record.json).
- D4-11 Install hints: MacOs "brew install ffmpeg", Linux "sudo apt install ffmpeg (or your distro's ffmpeg package)", Windows "winget install ffmpeg" (user wording). Every WARN fix mentions BLADE_FFMPEG.
- D4-12 Format switch suggestion: when the configured encoder is missing but the other format's encoder exists, the fix adds "or set BLADE_RECORD_FORMAT=<other>". VP8/libvpx is never suggested (values.rs: not offered).
</decisions>
