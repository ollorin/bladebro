<decisions>
Document each in a comment where implemented.
- D4-1 Std, not tokio, for the probe: the OnceLock initializer is sync, and later callers (Phase 5 encoder, RecordHub) must be able to call it from any context. A child with a stdout-drain thread plus a `try_wait` poll loop (10 ms) is bounded and needs no runtime. Doctor's async `run()` tolerates the bounded block (check_xvfb already runs a blocking std Command). Phase 5 callers inside the daemon runtime should wrap the first call in `spawn_blocking`.
- D4-2 BLADE_FFMPEG: blank or whitespace-only means unset (matches record config and platform.rs). If set, it must be an absolute path to an existing regular file that is executable (unix: any x bit) -> otherwise `OverrideUnusable { value, reason }` and the search stops there. Reasons: "must be an absolute path (no ~ expansion)", "not found", "is a directory", "not a regular file", "not executable (chmod +x)", or the stat error. Rationale: an explicit override that silently falls through would run a different binary than the user asked for (PITFALLS: PATH hijack).
- D4-3 PATH: entries via `std::env::split_paths`; empty and relative entries (".", "bin") are skipped (CWD binary hijack); first usable `ffmpeg` (`ffmpeg.exe` on Windows) wins. No PATHEXT handling: ffmpeg ships as .exe.
- D4-4 Known locations (in this order; all three lists compiled on every OS, selected by `TargetOs`):
  macOS: /opt/homebrew/bin, /usr/local/bin, <home>/.local/ffmpeg/bin, <home>/bin.
  Linux: /usr/bin, /usr/local/bin, /snap/bin, <home>/.local/bin.
  Windows: %LOCALAPPDATA%\Microsoft\WinGet\Links (only if LOCALAPPDATA set), C:\ffmpeg\bin, %SCOOP%\shims else <home>\scoop\shims, %ChocolateyInstall%\bin else C:\ProgramData\chocolatey\bin.
- D4-5 Probe: argv `[-hide_banner, -version]` then `[-hide_banner, -encoders]`; stdin/stderr null, stdout piped; per-call timeout 5 s (`PROBE_TIMEOUT`, same bound as doctor's Chrome --version); stdout read up to 1 MiB (`MAX_PROBE_OUTPUT`) then drained to io::sink so the child never blocks on a full pipe; on timeout kill + wait and return Err "timed out after 5s"; after exit wait at most 1 s for the drain thread (a grandchild may hold the pipe) else Err "output pipe stayed open"; non-zero exit -> Err "exited with <status>"; spawn error -> Err "cannot run <path>: <e>". If `-version` output has no `ffmpeg version` line -> Err "does not look like ffmpeg (first line: <<=80 chars>)". Windows: `CommandExt::creation_flags(0x0800_0000)` (CREATE_NO_WINDOW) inside `#[cfg(windows)]`.
- D4-6 Versions: no floor enforced. `is_old()` is true for a release major < 4; 04-02 shows it as a note. Date-stamped builds (gyan "2024-11-25-git-...") and `N-...` / `git-...` builds are `Git`, never a release with major 2024.
- D4-7 Encoders: only video encoders (flag column starts with 'V') after the "------" separator are collected; legend lines above it are ignored. No separator -> `listed = false`. Names used: VP9 "libvpx-vp9", H.264 "libx264"; "libvpx" (VP8) and the h264 hardware encoders (h264_videotoolbox/nvenc/qsv/amf/vaapi) are detectable through `has()` but nothing reports or uses them (VP8 not offered per values.rs/RESULTS.md).
</decisions>
